# Internationalization

Formatters, parsers, the translator and the validators follow the locale manager
(`getLocaleManager()` in `src/i18n/locale-manager.js`). Its `locale` defaults to the browser's;
changing it changes all of them:

```js
getLocaleManager().locale = 'nl-NL';
```

The locale manager also holds the month and day names, the AM/PM designators, the decimal and
group separators (all from `Intl`, and all overridable) and the `timeZone` dates are formatted and
parsed in: `'UTC'` by default (like the original toolkit), an IANA name, or `'local'`.

Every formatter, parser, validator and translator also takes its own `locale` (fixed) or
`localeManager` (to follow another manager): `new DateTimeFormatter({ locale: 'de-DE' })`. Each
module has a singleton (`getStringFormatter()`, `getDateTimeFormatter()`, ...) and convenience
functions that use it.

## Formatting strings and numbers

`StringFormatter#format` (`src/i18n/string-formatter.js`) is printf-like, with the syntax of the
original toolkit: `%[argnum$][flags][width][.precision]specifier`.

```js
formatString('%s has %d new messages.', 'Anna', 3);
formatString('%2$s, %1$s!', 'world', 'Hello'); // 'Hello, world!'
formatString('%08.3f', -3.14159); // '-003.142'
formatString("%'*8s", 'ab'); // '******ab'
formatString('%.2F', 1234.5); // '1,234.50' in English, '1.234,50' in Dutch
```

- Flags: `-` (justify left), `+` (sign), `0`, a space or `'c` (padding character).
- Specifiers: `%`, `b`, `c`, `d`, `u`, `e`, `E`, `f`, `F`, `g`, `G`, `o`, `s`, `x`, `X`. `f` always
  uses a period; `F` uses the locale's separators and digit grouping. The precision of `s`
  truncates.
- A missing argument throws a `RangeError`. A `%` that starts no placeholder is kept.

`formatNumber(value, options)` formats with `Intl.NumberFormat` options and the locale manager's
separators; `decimals` is a shortcut for a fixed number of fraction digits:

```js
formatNumber(1234.5); // '1,234.5'
formatNumber(3, { decimals: 2 }); // '3.00'
formatNumber(0.25, { style: 'percent' }); // '25%'
```

## Formatting dates and times

`DateTimeFormatter#format(format, timestamp)` (`src/i18n/date-time-formatter.js`) is like C's
`strftime`. Timestamps are milliseconds since the Unix epoch (or `Date` objects).

```js
const formatter = getDateTimeFormatter();
formatter.format('%A, %B %-d %Y', Date.UTC(2013, 7, 10)); // 'Saturday, August 10 2013'
formatter.format('%F %T %z', Date.now());
formatDate(Date.now(), DateTimeStyle.LONG); // 'August 10, 2013'
formatTime(Date.now(), DateTimeStyle.SHORT); // '2:05 PM'
formatDateTime(Date.now()); // 'Aug 10, 2013, 2:05:09 PM'
```

| Specifiers               | Meaning                                                             |
| ------------------------ | ------------------------------------------------------------------- |
| `%a` `%A`                | Short and long day name                                             |
| `%d` `%e`                | Day of the month, `01`-`31` and ` 1`-`31`                           |
| `%j`                     | Day of the year, `001`-`366`                                        |
| `%u` `%w`                | Day of the week, `1`-`7` from Monday and `0`-`6` from Sunday        |
| `%U` `%W` `%V`           | Week of the year from Sunday (`00`-`53`), from Monday, and ISO 8601 |
| `%b` `%h` `%B` `%m`      | Short and long month name, month `01`-`12`                          |
| `%C` `%y` `%Y` `%g` `%G` | Century, 2- and 4-digit year, 2- and 4-digit ISO week year          |
| `%H` `%k` `%I` `%l`      | Hour `00`-`23`, ` 0`-`23`, `01`-`12`, ` 1`-`12`                     |
| `%M` `%S` `%L`           | Minutes, seconds, milliseconds                                      |
| `%p` `%P`                | The locale's AM or PM, and in lowercase                             |
| `%z` `%Z`                | Offset from UTC (`+0200`) and time zone name (`CEST`)               |
| `%s`                     | Seconds since the Unix epoch                                        |
| `%r` `%R` `%T` `%D` `%F` | `%I:%M:%S %p`, `%H:%M`, `%H:%M:%S`, `%m/%d/%y`, `%Y-%m-%d`          |
| `%c` `%x` `%X`           | The locale's date, date and time, and time                          |
| `%n` `%t` `%%`           | Newline, tab, percent sign                                          |

As in the original toolkit, `%c` is the preferred date and `%x` the preferred date and time (C
swaps them). Their length is set by the `dateStyle` and `timeStyle` properties
(`DateTimeStyle.SHORT`, `MEDIUM`, `LONG` or `FULL`). The glibc flags `-` (no padding), `_`
(spaces), `0` (zeros) and `^` (uppercase) may follow the `%`, as in `%-d`.

## Parsing numbers

`IntegerParser` and `DoubleParser` (`src/i18n/integer-parser.js`, `double-parser.js`) return a
number or `null`:

```js
parseInteger('1,234'); // 1234 in English
parseDouble('1.234,5'); // 1234.5 in Dutch
new DoubleParser({ locale: 'fr-FR' }).parse('1 234,5'); // 1234.5
```

The whole text must be a number, group separators must be in the right places, and integers must
be safe integers. Unicode minus signs and common non-Latin digits are accepted. In lenient mode (the
default, as in the original toolkit) whitespace is ignored and the text is also tried with the
decimal and group separators swapped, so `1,5` is 1.5 in English too; `lenient: false` accepts only
the locale's notation. `normalize(text)` returns the canonical JavaScript notation (`'1234.5'`).

## Parsing dates and times

`DateTimeParser` (`src/i18n/date-time-parser.js`) reads dates as people type them, in the locale
and in English. It returns `null` for anything it does not fully understand or that is not a real
date (`2/30/2013`).

```js
parseDate('10 aug 2013'); // Date at midnight in the time zone
parseDate('8/10/2013'); // In the locale's order: August 10 in the US, October 8 in Britain
parseDate('2013年8月10日');
parseDate('next friday');
parseDate('3 days ago'); // Also 'vor 3 Tagen' in German, via Intl.RelativeTimeFormat
parseTime('2:05 PM'); // 50700000, milliseconds since midnight
parseDateTime('tomorrow at 14:30');
parseDateTime('2013-08-10T14:05:09Z');
getDateTimeParser().parseExact('10-08-2013', '%d-%m-%Y');
```

Understood are numeric dates in the locale's order (and ISO dates), month and day names and their
prefixes, ordinals (`10th of August`, `1er août`), year, month and day markers (`年`, `월`, `г.`),
two-digit years (up to `twoDigitYearMax` in this century), and relative dates: `now`, `today`,
`yesterday`, `the day after tomorrow`, `last/this/next week/month/year`, `in 2 weeks`, day names
(the next one) and month names. The locale's own words for these come from
`Intl.RelativeTimeFormat` (`gisteren`, `übermorgen`). `referenceTime` fixes "now" for tests.

`parseExact(text, format)` parses a text in a formatter format, which is how a date edit reads back
its own format.

## Translating

The translator (`src/i18n/translator.js`) holds a dictionary of entries per language. An
identifier can be a key or the source text; without a translation it falls back to the identifier
(or to the `fallbackLanguage`). Translations are formatted with the string formatter, so `%1$s`
reorders arguments.

```js
const translator = getTranslator();
translator.addEntries({
    'Open': 'Openen',
    '%s of %s': '%2$s van %1$s',
    '%d files': { '=0': 'Geen bestanden', one: '%d bestand', other: '%d bestanden' },
}, 'nl');

tr('Open'); // 'Openen' when the language is Dutch
tr('%d files', 3); // '3 bestanden'
trn('%d file', '%d files', count); // Like gettext's ngettext
```

Plural entries are chosen with `Intl.PluralRules` of their language by the first argument, with
exact matches (`'=0'`) first. Lookups try the locale (`nl-BE`), then its language (`nl`), then the
fallback language. A `loader` loads dictionaries on demand; it may return a promise, and
`whenLoaded()` waits for pending loads:

```js
translator.loader = async (language) => (await fetch(`/i18n/${language}.json`)).json();
```

The translator emits `language-change`, `entries-change` and `change` (after either).

A `TranslatedText` (`src/i18n/translated-text.js`) is an immutable identifier with arguments whose
`text` follows the language; it emits `text-change` when that changes, and `String(text)` gives the
current translation. `__(id, ...args)` creates one, like the original toolkit's shortcut, and
`__n(singular, plural, count, ...args)` one with plural forms. In the builder it is
`{ type: 'translated-text', id: 'Open', arguments: [] }`.

## Validators

Validators (`src/data/validators/`) check the text of line edits:

```js
const validator = new IntegerValidator({ minimum: 0, maximum: 100 });
validator.validate('42'); // true
validator.fixup('1000'); // '100', clamped and in the locale's notation
validator.message; // 'Enter a whole number from 0 to 100.', translated
validator.parse('42'); // 42, or null when not valid
```

- `Validator` is the base class: `validate(text)` (also as the original `isValid`), `fixup(text)`,
  `message` (a translated description of the valid input, or your own), and `allowEmpty`. It emits
  `change` when its settings or its locale change, so texts can be validated again.
- `IntegerValidator` and `DoubleValidator` use the parsers, with `minimum`, `maximum`, `lenient`
  and, for doubles, `decimals`.
- `RegexpValidator` checks that its `regexp` (a `RegExp` or a string) matches the whole text.

Subclasses implement `_validate(text)`, which only gets non-empty texts. The builder types are
`integer-validator`, `double-validator` and `regexp-validator`.
